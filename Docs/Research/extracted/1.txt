Session Composition & Program Settings Taxonomy for Helm: Engineering Specification & Scientific Framework
1. Executive Summary
The current architecture of Helm evaluates daily volume allocation through a simplistic 1:1 muscle-to-exercise assignment model. In PrescriptionEngine, a session is constructed by assigning exactly one exercise to each target muscle defined within the active day's split. On a Pull day—defined in SessionSplitPlanner as back and biceps—the engine selects one movement for the back and one movement for the biceps. When the weekly volume target for back (e.g., 12 hard sets) is distributed across two weekly Pull exposures, the engine assigns 6 hard sets to the single back exercise in a single workout.
This 1:1 design produces a severe structural failure: thin sessions consisting of only 2 exercises, where total weekly set targets are met by dumping high set volumes onto single movements.
Current Helm Engine Allocation (Pull Day Example):
  Back Muscle Target  ---> 1 Exercise Picked (e.g., Lat Pulldown) ---> Assigned 6 Hard Sets
  Bicep Muscle Target ---> 1 Exercise Picked (e.g., Bicep Curl)   ---> Assigned 5 Hard Sets
  Result: 2 Exercises, 11 Sets (Violates Gym Practice Norms & Biomechanical Principles)
From a sports science and neuromuscular perspective, dumping 5 to 6 hard sets onto a single exercise in one session introduces significant physiological drawbacks:
Intra-Session Diminishing Returns and Junk Volume: Empirical meta-regressions demonstrate that hypertrophic stimulus per set decays rapidly past 3 to 4 sets for a given movement vector in a single session. Beyond this threshold, acute localized neuromuscular fatigue, calcium ion handling impairment, and excitation-contraction coupling degradation accumulate, yielding "junk volume" that elevates systemic fatigue without stimulating additional muscle protein synthesis.
Inadequate Regional Muscle Activation: Complex muscle groups like the latissimus dorsi, trapezius, and quadriceps cannot be fully stimulated by a single biomechanical movement. Biomechanical research confirms that heterogeneous muscle growth (regional hypertrophy) requires varied loading angles, resistance profiles, and muscle lengths. A single vertical pull fails to recruit the mid-trapezius and rhomboids as effectively as a horizontal row.
Product Defect: A two-exercise session fails to align with realistic gym training durations, rendering the application's prescriptions incomplete to lifters regardless of mathematical accuracy.
To resolve this defect, Helm must adopt a Movement Pattern Session Composer Architecture. This framework shifts the unit of session design from gross muscle labels to functional movement pattern slots (e.g., Vertical Pull, Horizontal Pull, Elbow Flexion). The composer enforces a maximum cap of 3 to 4 sets per exercise, dynamically expands pattern slots based on the athlete's explicit Session Duration Budget, and splits muscle volume across complimentary movement vectors.

Educational essays within the Sources UI must not directly manipulate engine calculations. Instead, Helm employs a Methodology Bridge Pattern. The methodology text remains an educational citation, while the typed setting executes deterministic adjustments within the engine.

Session Duration Budget & Capacity Matrices
Session set capacity is constrained by the athlete's explicit Session Duration Budget ($T_{budget}$). The duration required for a session ($T_{total}$) is calculated using warm-up allocations, set execution times, rest intervals, and exercise transition times:
$$T_{total} = T_{warmup} + \sum_{i=1}^{E} \left( N_{sets, i} \cdot T_{exec} + (N_{sets, i} - 1) \cdot T_{rest, i} \right) + (E - 1) \cdot T_{trans}$$
Where:
$T_{warmup} = 5.0\text{ minutes}$ (general warm-up baseline).
$T_{exec} = 0.75\text{ minutes}$ ($45\text{ seconds}$ total time-under-tension per set).
$T_{rest, i} = 2.0\text{ minutes}$ for primary compound slots; $1.25\text{ minutes}$ for secondary isolation slots.
$T_{trans} = 2.0\text{ minutes}$ (setup and movement transition time between distinct exercises $E$).

Volume Allocation, Set-Splitting, & Exercise Cap Rules
Per-Exercise Set Cap: No single exercise may receive more than 4 working sets in a single workout session. If a target muscle requires 6 hard sets in a workout, the engine must split that volume across two distinct movement pattern slots (e.g., 3 sets of Vertical Pull + 3 sets of Horizontal Row).
Primary vs. Secondary Allocation Ratios: Mandatory primary compound slots are assigned 3 to 4 working sets. Secondary isolation slots are assigned 2 to 3 working sets.
Session Set Minimum Threshold: A standard 60-minute session must contain a minimum of 12 hard sets across at least 4 distinct exercises.
Criteria for 2-Exercise Sessions: A 2-exercise session is classified as an engine composition defect unless one of the following explicit parameters is present:
The user's Duration Budget is explicitly configured to 30 Minutes.
The active microcycle is a designated Deload Phase (where overall volume is scaled down by $50\%$).
An active Injury / Medical Constraint limits the session to specific isolated movements.
Handling Residual Weekly Volume: If remaining weekly sets for a target muscle exceed the daily session budget ($T_{budget}$), excess volume is automatically distributed to subsequent split exposures within the same week.
Deterministic Session Composer Algorithm & Logic
The SessionComposer executes in linear steps without reliance on LLM inputs:
INPUTS:
  athlete_profile : AthleteProfile (Experience, DurationBudget)
  split_day       : SplitDayEnum (PUSH, PULL, LEGS, UPPER, LOWER, FULL_BODY)
  weekly_targets  : Map<MuscleGroup, Int> (Remaining weekly hard sets)
  rem_sessions    : Map<MuscleGroup, Int> (Remaining session exposures this week)
  equipment_filter: Bitmask (Allowed equipment IDs)
  selection_bias  : BiasEnum (BALANCED, STRETCH_FOCUSED, LOW_FATIGUE)

OUTPUT:
  SessionPlan : Struct { exercises: List<ExerciseAssignment>, total_sets: Int, estimated_duration: Int }

PROCEDURE ComposeSession(athlete_profile, split_day, weekly_targets, rem_sessions, equipment_filter, selection_bias):

  1. Calculate Target Daily Volume per Muscle:
     daily_muscle_targets = Map<MuscleGroup, Int>()
     FOR EACH muscle IN split_day.target_muscles:
       daily_muscle_targets[muscle] = CEIL(weekly_targets[muscle] / rem_sessions[muscle])

  2. Determine Session Capacity Limit:
     T_capacity = GetMaxSetBudget(athlete_profile.DurationBudget) // e.g., 15 sets for 60 min

  3. Select and Order Pattern Slots:
     active_slots = List<PatternSlot>()
     active_slots.AppendAll(GetMandatoryPrimarySlots(split_day))
     
     // Add secondary slots if volume and time capacity allow
     FOR EACH muscle IN split_day.target_muscles:
       IF daily_muscle_targets[muscle] > 4 OR active_slots.ContainsMuscle(muscle) == FALSE:
         active_slots.Append(GetSecondarySlotForMuscle(muscle))

  4. Exercise Selection & Set Allocation:
     session_exercises = List<ExerciseAssignment>()
     accumulated_sets = 0

     FOR EACH slot IN active_slots:
       IF accumulated_sets >= T_capacity:
         BREAK

       candidate_catalog = FilterCatalog(slot, equipment_filter)
       selected_lift = RankAndSelect(candidate_catalog, selection_bias)
       
       target_muscle = slot.PrimaryMuscle
       needed_sets = daily_muscle_targets[target_muscle]
       
       // Enforce exercise cap of 4 sets max
       sets_to_assign = MIN(needed_sets, 4)
       sets_to_assign = MIN(sets_to_assign, T_capacity - accumulated_sets)
       
       IF sets_to_assign > 0:
         session_exercises.Add(ExerciseAssignment(selected_lift, slot, sets_to_assign))
         accumulated_sets += sets_to_assign
         daily_muscle_targets[target_muscle] -= sets_to_assign

  5. Construct and Return SessionPlan:
     est_duration = CalculateDuration(session_exercises)
     RETURN SessionPlan(session_exercises, accumulated_sets, est_duration)

Policy for Mid-Block Experience Adjustments
When an athlete modifies their Experience Level during an active mesocycle block:
Immediate Engine Action: Structural rules (Max sets per exercise, RIR targets, movement complexity filters) update immediately for all remaining uncompleted sessions.
Deferred Engine Action: Baseline MEV/MRV volume landmark seeds remain fixed for the active block. Landmarks reseed only when initiating a new mesocycle block, preserving volume progression tracking.

Deterministic Mechanics of Structured Emphasis
Volume Acceleration: Adds $+2$ sets/week (MODERATE) or $+4$ sets/week (HIGH) to the target muscle's MEV/MRV landmarks, capped at the absolute MRV ceiling.
Slot Ordering Elevation: Promotes pattern slots matching the emphasized muscle to the front of the session order, ensuring work is performed prior to systemic fatigue.
Isolation Slot Guarantee: Mandates dedicated isolation pattern slots (e.g., Biceps emphasis guarantees both Supinated Bicep Curl and Neutral Hammer Curl slots within Pull day composition).
5. LLM Coach Behavioral Contract & Thin Session Detection
Thin Session Diagnostic Criteria
The LLM Coach monitors session quality using deterministic diagnostic conditions. A session is flagged as "thin" if any of the following parameters are satisfied:
$$\text{ThinSession} = \begin{cases} \text{TRUE} & \text{if } N_{sets} < 10 \text{ AND } T_{budget} \ge 60\text{ min} \\ \text{TRUE} & \text{if } E_{count} < 4 \text{ AND } T_{budget} \ge 60\text{ min} \\ \text{TRUE} & \text{if Mandatory Primary Slot is Unfilled} \\ \text{FALSE} & \text{otherwise} \end{cases}$$

6. Migration Engineering Roadmap & Risk Analysis
Phased Implementation Strategy
Phase 1: Immediate Prescription Engine Patch (Hotfix)
  ├── Enforce 4-set maximum cap per exercise across existing allocation logic.
  └── Enforce minimum 2-pattern-slot split for muscles requiring >4 sets in a single session.

Phase 2: SessionComposer Engine Architecture (Core Release)
  ├── Implement full Pattern Slot Taxonomy and Movement Pattern Catalog.
  ├── Deploy Session Duration Budget Matrix and set capacity engine.
  └── Decouple exercise counts from simple 1:1 muscle group mappings.

Phase 3: Settings IA & Coach Protocol Integration (Refinement)
  ├── Migrate Settings UI to formal IA (separating sources from typed parameters).
  ├── Deploy structured EmphasisProfile JSON configuration.
  └── Enforce Coach Thin Session detection and clamped proposal schema.
Failure Modes, Edge Cases, & Mitigation Matrix

Engineering Acceptance Criteria
SCENARIO 1: Default 60-Minute Pull Day Composition
  GIVEN an athlete on PPL split with a 60-minute Duration Budget
  WHEN SessionComposer generates a Pull Day session
  THEN the session MUST contain >= 4 distinct exercises
  AND total session working sets MUST fall between 13 and 16 sets
  AND no single exercise MUST exceed 4 hard sets
  AND pattern slots MUST include at least 1 Vertical Pull, 1 Horizontal Pull, and 1 Elbow Flexion.

SCENARIO 2: Equipment Filter Respect
  GIVEN an athlete with Allowed Equipment set to {DUMBBELL, BODYWEIGHT}
  WHEN SessionComposer builds any session
  THEN 100% of selected exercises MUST match the allowed equipment bitmask.

SCENARIO 3: Deterministic Re-Plan Triggers
  GIVEN an active mesocycle
  WHEN the athlete changes Duration Budget from 60 min to 45 min
  THEN uncompleted sessions MUST deterministically re-plan to set capacities <= 12 sets
  AND completed historical sessions MUST remain unmodified.
